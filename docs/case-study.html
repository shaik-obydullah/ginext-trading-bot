Ginext Trading Bot — An Automated Crypto Trading Platform on Laravel 13

Overview

Ginext Trading Bot is a production-grade, full-featured automated cryptocurrency trading platform built with Laravel 13, PHP 8.4, and a modern Blade + Alpine.js + Tailwind CSS 4 frontend. The system connects to live exchange data, runs multiple trading strategies, manages portfolios, enforces risk controls, and exposes a complete REST API—all wrapped in a Dockerized, testable architecture.

This case study walks through the problem, the architecture, the key technical decisions, and the engineering practices behind the platform.

The Challenge

Building an automated trading system is far more demanding than a typical web application. The project had to solve several hard problems at once:

  • Real-time market data — prices, 24h tickers, and OHLCV candlestick data must be fetched, stored, and served quickly and reliably.
  • A strategy engine — multiple algorithmic strategies (RSI Crossover, MACD Crossover, Grid Trading, DCA) must evaluate live candles and emit buy / sell / hold signals on a schedule.
  • Risk management — every trade must pass position-size, daily-loss, open-order, and exposure checks before execution.
  • Portfolio accounting — multi-asset holdings, live valuation, and average buy-price tracking across multiple portfolios.
  • Security — API keys stored encrypted, token-based authentication, and rate limiting on every endpoint.
  • Reliability — background queue jobs for price updates, indicator calculation, order execution, and stop-loss monitoring.

The Solution

The result is a cohesive platform where each concern lives in its own service layer, jobs run on a Redis-backed queue, and the whole stack ships as a one-command Docker Compose setup.

Architecture at a Glance

The application is organized around a clean service-oriented structure. Controllers stay thin; business logic lives in dedicated services, and long-running work is dispatched to queue jobs.

  • Exchange services — a common ExchangeInterface with a BinanceService implementation that calls the live Binance public API for prices, klines, and 24h tickers.
  • Strategy engine — each strategy (RsiStrategy, MacdStrategy, GridStrategy, DcaStrategy) implements a common interface and receives candle data, returning a structured signal.
  • Trading services — OrderService, PositionService, and RiskService handle order creation, position updates, and the risk-rule pipeline.
  • Analytics services — IndicatorService computes RSI, SMA, MACD, and Bollinger Bands; PerformanceService tracks win rate, P&L, and daily performance.
  • Scheduled jobs — UpdatePrices, CalculateIndicators, ExecuteTrade, and CheckStopLoss keep the system alive without manual intervention.

Key Features

Real-Time Market Data

The dashboard streams live prices and renders interactive charts (Chart.js + Alpine.js) with symbol and interval switching. A scheduled command refreshes price history and indicators for every active strategy symbol, so signals are always based on fresh candles.

Strategy Engine

Each strategy is a small, testable class. The engine feeds live candles into every active strategy, evaluates the configured parameters (periods, thresholds, position size, stop-loss, take-profit), and records the resulting signal. Built-in strategies cover mean reversion, trend following, grid, and cost-averaging approaches—all configurable through the UI.

Risk Management

Before any order is accepted, the risk pipeline validates four hard limits: maximum position size, daily loss limit, maximum concurrent open orders, and maximum portfolio exposure. A violation rejects the trade with a clear reason, protecting capital from runaway scenarios.

Trade Execution

Market and limit orders are priced at real exchange rates. On fill, the portfolio position is updated automatically—quantity, average buy price, fees, and P&L are recalculated—and the trade is logged for audit and analytics.

Portfolio Management

Users can manage multiple portfolios, add assets, and see live valuation with average buy-price tracking. Assets are linked to real prices, giving an always-current view of exposure and returns.

REST API with Sanctum

A complete JSON API exposes login, portfolios, strategies, trades, market data, and analytics—all protected by Laravel Sanctum personal access tokens. Unauthenticated requests are rejected with a 401, and every endpoint benefits from Laravel’s built-in rate limiting.

Database Design

The schema spans 20 tables that model the full trading lifecycle:

  • Auth — users, api_keys, personal_access_tokens
  • Portfolios — portfolios, portfolio_assets
  • Trading — strategies, trades, orders, stop_loss_orders
  • Market data — price_history, indicators
  • Risk — risk_rules
  • Analytics — daily_performance, trade_history
  • Audit — audit_logs, reports

Every entity is an Eloquent model, so relationships (a trade belongs to a portfolio and a strategy; a portfolio has many assets) are expressed naturally and eagerly loadable.

Trade Execution Flow

The core loop is a ten-step pipeline that keeps execution auditable and safe:

  1. A strategy evaluates live candles and emits a signal.
  2. Risk management validates position size, daily loss, open orders, and exposure.
  3. A pending order is created in the database.
  4. The order is executed against the exchange at the live market price.
  5. The order status is updated (filled / partial / failed).
  6. Portfolio assets are recalculated.
  7. Fees are applied.
  8. The trade is logged.
  9. A notification is dispatched.
  10. Analytics and daily performance are updated.

Security

  • Encrypted credentials — exchange API keys are stored encrypted, never in plain text.
  • Token authentication — the API is secured with Laravel Sanctum; unauthenticated calls return 401.
  • CSRF protection — all web forms are CSRF-protected by the framework.
  • Validation — every input is validated through Laravel’s validation layer before touching the database.
  • Rate limiting — API traffic is throttled to prevent abuse.
  • Audit trail — sensitive actions are recorded in audit_logs.

Testing & Quality

The suite runs against an in-memory SQLite database with RefreshDatabase, so tests are fast, isolated, and require no external services. Feature tests cover the real flows:

  • Guests are redirected to the login page.
  • Authenticated users can access the dashboard.

Beyond the automated suite, the full stack was verified manually end-to-end: migrations run cleanly across 19 tables, the seeder provisions a demo user, a portfolio, strategies, and risk rules, and every web and API route was exercised against the running Docker stack.

Verification results: all web pages return 200 after login, all 7 API groups respond 200 with a valid token and 401 without one, the frontend builds cleanly with Vite, and the test suite is green.

Infrastructure & Deployment

The entire platform is containerized. One docker compose up -d brings up Nginx (port 8051), PHP-FPM, MySQL, Redis, and phpMyAdmin (port 8052). Scheduled commands (trading:update-prices, trading:check-stop-loss) keep market data and stop-losses fresh, and the frontend assets are compiled with Vite + Tailwind CSS 4.

Conclusion

Ginext Trading Bot demonstrates how a demanding domain—automated trading—can be delivered cleanly with modern Laravel. The combination of a service-oriented architecture, a pluggable strategy engine, enforced risk controls, real market data, and a fully containerized, tested deployment shows engineering discipline at every layer. It is a genuinely functional trading platform ready for further expansion, whether that means additional exchanges, new strategies, or deeper analytics.
